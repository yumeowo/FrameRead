# 原始选题讨论稿

来源：用户与 AI 的选题讨论，由用户于 2026-11-11 提供。

以下保留用户消息中代码围栏内的原始内容，不对其中的命名、功能优先级、平台能力假设和排版进行修订。扩展与澄清见 [PRD](PRD.md)。原稿中的能力描述属于产品设想，不是平台可用性证明。

命名补充：用户已于 2026-11-11 确认正式名称为 **FrameRead**，下文的 DeepDeck 为早期代号。

---

把数据源聚焦到 B站/YouTube 技术视频 + 静态文章，并将阅读体验修正为 “硬核 Markdown 深度讲义为主、交互式动态组件为辅”，这个产品的自用属性就彻底立住了——它不再是一个花哨的“卡片玩具”，而是一个帮你把收藏夹里积灰的半小时硬核技术视频，转化为“图文精读笔记 + 机制微交互验证 + 记忆闪卡”的个人知识内化工作台。

以下从 MVP 产品需求文档（PRD） 视角给出完整产品设计，暂将产品代号定为 DeepDeck，现阶段仅定义业务闭环、功能边界与交互体验，不锁定底层技术选型与架构实现。

一、 产品定位与核心设计原则

1. 解决的核心痛点

线性看视频太慢，看普通 AI 总结又太浅：30 分钟的架构解析、源码走读或 Conference 演讲视频，二倍速看容易漏细节、来回拖进度条看 PPT/代码极其费劲；而市面上的一键“AI 视频总结”只会输出几条干瘪的大纲，丢失了最关键的技术上下文、推导过程与关键配图，看完依然什么都没学会。

平台围墙与登录态门槛：高频使用的 B站收藏夹、B站 AI 字幕流、高清画面源，以及部分受限的 YouTube 列表，脱离用户登录态根本无法提取有效内容。

2. 核心体验原则：“80 / 20 混合精读法则”

拒绝把完整的技术逻辑切碎成零散卡片。产品阅读流遵循 80% 硬核图文（Markdown 优先） + 20% 嵌入式动态交互组件 的配比：

Markdown 负责“讲透上下文”：承担深水区知识交付，完整保留技术背景、公式推导、代码块对比、结构化表格，以及从原视频精准截取的架构图/PPT/代码特写帧。

动态交互组件负责“卡住关键节点”：只在解析前的范围确认、正文关键机制的理解自测、以及读完后的闪卡分拣三个高价值节点介入，用原生触控交互替代低效打字。

二、 核心用户旅程（End-to-End User Flow）

随手投递 / 收藏夹拉取：刷 B站/YouTube 或技术博客时，通过移动端系统分享面板（Share Sheet）一键投递到 DeepDeck，或直接在 App 内浏览已授权同步的“稍后再看 / 指定收藏夹”勾选导入。

解析范围圈定（针对长内容）：若导入的是超过 20 分钟的长视频或多 P 视频，系统先快速返回目录大纲/分P列表，弹出轻量交互卡片让用户勾选“本次只精读哪几节”及“关注侧重点”，避免全量盲目生成。

异步多模态提炼：后台提取字幕/文稿，定位视频中讲解架构图、PPT 翻页与核心代码段的时间点并截取高清关键帧，生成结构化混合讲义（支持后台排队，完成后本地通知提醒）。

沉浸式图文精读 + 行内微交互：阅读深度 Markdown 笔记，查看嵌在正文中的视频原图（点击时间戳可一键空降原视频对应秒数回看）；遇到关键概念节点时，直接在行内动态组件上动手完成时序推演或辨析自测。

闪卡分拣与归档闭环：文末自动汇总候选记忆闪卡（结合正文重点与你在行内自测中答错的薄弱项），左右滑动快速筛选、行内微调挖空词，一键存入内置复习队列或导出至外部记忆工具（如 Anki）。

三、 MVP 功能需求拆解

模块 1：多源接入与站点登录态管家（Ingestion & Auth）

这是保障视频内容能真正抓下来的前置底座，核心追求“投递零阻力、授权透明可控”。

多渠道内容输入：

支持粘贴或通过移动端系统级分享菜单直接传入 B站视频链接（含单视频、多 P 视频）、YouTube 视频链接及常规静态技术文章 URL。

支持绑定并按需下拉刷新 B站“稍后再看”或指定公开/私密收藏夹列表，批量勾选待精读条目。

站点登录态授权管理：

提供内置安全登录页（支持扫码或网页授权登录 B站 / YouTube），获取读取字幕轨道（CC 字幕 / AI 生成字幕）、收藏夹列表及清晰视频流所需的用户凭证。

凭证健康度状态栏：在设置页直观展示各站点授权状态（有效 / 即将过期 / 已失效），当解析任务因登录态失效受阻时，弹出快捷重授权引导并自动恢复排队任务。

解析前置交互确认（Pre-flight Triage）：

当检测到超长视频、合集分 P 或缺失现成字幕（需耗费额外算力进行语音转写）时，任务暂停并向用户呈现交互式配置卡：展示章节列表供多选裁剪，确认后再进入深度生成阶段。

模块 2：音视频多模态内容提炼（产品能力要求）

解决纯字幕转写“只闻其声、不见其图”导致的理解断层。

多级文稿获取策略：优先提取平台原生人工字幕与官方 AI 字幕；无字幕视频支持触发语音转写兜底（在 MVP 阶段可限制单次转写时长上限以控制等待时间）。

高价值视觉关键帧截取（Smart Keyframes）：

过滤无意义的人像口播画面，重点识别并截取视频中的 PPT 结论页、系统架构图、流程图、终端报错输出及 IDE 代码演示画面。

每张插入正文的视频截图均自动附带精确时间戳角标（如 [14:28]）。

原视频精准回溯（Deep-Link 空降）：

阅读讲义时若觉得某张截图细节不够或想听原博主的讲解语气，点击时间戳角标即可通过小窗播放器定位播放，或直接唤起手机上的 B站 / YouTube 客户端精准空降到该秒数。

模块 3：混合式深度精读视图（Hybrid Study Reader）

产品的核心阅读器界面，严格保障技术干货的信息密度与阅读沉浸感。

内容形态分层承担的产品职责具体展现与交互规范主干层：硬核 Markdown 讲义完整交代技术背景、核心原理推导、优劣势权衡与实现细节支持多级目录大纲跳转、代码块语法高亮与一键复制、数学公式渲染、结构化对比表格、以及带时间戳锚点的可缩放视频关键帧配图。穿插层：行内认知检验组件打破被动浏览惯性，在易混淆逻辑处检验真实理解度（每篇克制在 2–4 处）紧跟在核心章节末尾嵌入原生交互块，例如： • 机制排序/连线卡：排列协议握手步骤或生命周期执行顺序； • 情景排障单选卡：给定边界条件判断输出结果，选错即时展开针对性纠偏解析； • 代码差异/填空微卡：补全核心算法缺失的关键判断条件。辅助层：划词/指图局部追问解决阅读中途卡壳，且不破坏主线阅读位置选中某段复杂 Markdown 文本或长按某张视频截图发起追问，底部弹出抽屉解答；有价值的补充解释可一键“转化为正文批注块”持久化留在当前段落下方。

模块 4：零摩擦闪卡工坊与导出（Flashcard Triage & Sync）

打通“读懂”到“记住”的最后一公里，解决手机端手动制卡极度繁琐的痛点。

自适应候选制卡：系统不仅基于文章重点生成卡片，还会重点捕获用户在阅读过程中“做错的行内检验题”与“主动发起追问的难点”，生成高针对性的候选卡（支持基础问答卡、关键词挖空卡 Cloze、以及带视频架构图截图的图文问答卡）。

卡片快速分拣台（Triage Deck）：

文末提供原生卡片审阅组件：支持右滑采纳、左滑丢弃、点击直接在原卡上修改提问措辞或切换挖空高亮词。

开放的数据归宿（不锁死数据）：

轻量内循环：App 内置精简的每日待复习卡片流（基于间隔重复算法调度），适合通勤路上随手刷 5 分钟。

外部生态导出：支持一键导出标准格式文件（如 .apkg / Markdown / CSV），无缝导入你现有的主力复习软件生态。

四、 MVP 页面信息架构（极简 4 视图结构）

为控制个人毕设的客户端 UI 工作量，MVP 砍掉所有冗余层级，仅保留 3 个主导航 Tab + 1 个沉浸详情页：

待读收件箱（Inbox Tab）：上方为快速链接粘贴框与已绑定收藏夹同步入口；下方按状态展示条目列表（待配置范围 / 后台提炼中 / 已就绪待读 / 已归档）。

混合精读页（Study Reader — 核心视图）：顶部为源信息与目录抽屉，主体为“Markdown 讲义 + 视频关键帧 + 嵌入式动态交互组件”混合流，底部衔接“候选闪卡分拣台”。

每日复习页（Review Tab）：极简闪卡翻转自测界面（认识 / 模糊 / 忘记），展示今日待巩固队列。

连接与设置页（Settings Tab）：B站 / YouTube 登录态授权管理与健康度检测、默认精读偏好设置（如讲解颗粒度、语言偏好）、闪卡批量导出工具。

五、 MVP 范围控制（明确 P0 / P1 与不做事项）

在进入架构设计前，先把 MVP 的边界钉死，确保体量精悍、核心亮点突出：

P0（MVP 必做核心闭环）：

B站、YouTube 单链接解析 + 系统分享面板一键投递 + 内置登录态授权管理；

静态技术文章 URL 正文清洗与接入；

字幕提取 + 基于时间锚点的视频关键帧截取与原视频跳转；

长视频前置章节勾选交互组件；

Markdown 深度讲义渲染 + 3 种核心行内交互组件（步骤排序、概念辨析、代码挖空）+ 文末闪卡滑动分拣组件；

本地闪卡存储与标准格式导出。

P1（核心跑通后的体验加分项）：

B站“稍后再看”与指定收藏夹列表的自动拉取同步；

无字幕视频的离线/云端语音转写兜底；

划词与指图的局部上下文追问转正文批注。

Out of Scope（MVP 明确不做，防工作量失控）：

不做完整离线视频下载器与全功能视频播放器（只存文本、结构化数据与关键帧静态图，看原视频直接时间戳深链拉起官方客户端或轻量内嵌 Web 播放）；

不做全视频逐帧视觉大模型理解（对于纯画面无配音的操作录屏不做强支持，聚焦“有语音/字幕讲解 + 关键视觉画面辅助”的知识类视频）；

不做用户注册登录、云端多账号社交广场与评论区（纯个人知识工具定位）。

​在毕设论文中，你可以直接采用“短代号 + 学术副标题”的组合（例如：FrameRead：基于 A2A 与生成式 UI 的多模态技术内容精读与内化系统），既有真实独立产品的辨识度，又符合工科答辩的严谨度。
