# FrameRead

面向个人自用的技术内容精读与知识内化工作台：将 B站 / YouTube 技术视频与静态技术文章转化为可溯源的 Markdown 深度讲义，辅以机制自测、闪卡分拣与间隔复习。

当前处于需求整理阶段，仅有项目文档，尚未确定技术栈、客户端平台或架构，也没有可运行的应用、构建命令和测试套件。

## 项目文档

| 文档 | 用途 |

| [完整 PRD](docs/product/PRD.md) | 产品目标、MVP 范围、功能规则、异常路径、验收标准与待决问题 |
| [原始讨论稿](docs/product/initial-concept.md) | 保留选题原文，作为需求来源，不代表所有能力已验证 |

## 当前约定

- 正式名称确认为 **FrameRead**；早期代号 **DeepDeck** 仅保留在原始讨论稿中。
- 产品主线是“导入 → 范围确认 → 提炼 → 精读与自测 → 制卡 → 复习 / 导出”。
- 坚持 Markdown 讲义为主、少量行内交互为辅；不扩展成视频平台、卡片信息流或社交产品。
- P0 / P1、拟议参数与能力验证边界以 PRD 为准；文档目标不等于已经实现。
- A2A 与生成式 UI 仍是论文方向候选，不构成已选技术方案。

## 文档检查

目前可执行的基础检查：

```bash
git diff --check
```

该命令不检查未跟踪文件，也不验证链接、产品可行性或文档内容。新增文档还需检查相对链接、需求编号与范围一致性。确定技术栈后，在此补充实际可运行的安装、开发、测试与构建命令。
